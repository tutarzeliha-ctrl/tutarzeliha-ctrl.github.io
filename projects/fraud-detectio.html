The Problem

The e-commerce platform was processing 10,000+ daily transactions with a manual fraud detection system achieving only 25% true positive rate. This resulted in:

  • 45% false positive rate - Legitimate transactions blocked
  • 2+ hour detection latency - Fraudsters complete transactions
  • Manual review bottleneck - Cannot scale
  • $200K+ annual loss - Undetected fraud

The Solution

Built a real-time streaming fraud detection pipeline using CDC (Change Data Capture) with Kafka for sub-100ms detection and machine learning for pattern recognition.

Architecture
PostgreSQL Database
        ↓
    Debezium CDC (real-time capture)
        ↓
    Apache Kafka (streaming)
        ↓
    Apache Spark Streaming (pattern detection)
        ↓
    ML Model (Random Forest - 98% accuracy)
        ↓
    Prefect Orchestration
        ↓
    Slack Alerts + Database Update

Key Learnings

Technical
  • CDC is critical for real-time: Debezium polling vs change streams
  • Kafka partitioning: Transaction ID as key prevents duplicates
  • Spark windowing: Tumbling windows for feature aggregation
  • ML retraining: Monthly updates with new fraud patterns
Operational
  • Monitoring: Track latency p99 and model accuracy metrics
  • Alerting: Alert on accuracy drift (>2% drop)
  • Scaling: Process 10K TPS with 5-node Spark cluster
  • Testing: Chaos testing for Kafka broker failures
