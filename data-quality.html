The Problem

Data quality issues are expensive and time-consuming to diagnose:

  • 2-4 hours per incident - Manual root cause analysis
  • Manual documentation - Data dictionaries become outdated
  • No anomaly detection - Issues discovered by end users
  • Knowledge silos - Only technical leads understand pipelines
  • 40+ hours/month - Wasted on documentation updates

The Solution

Built an intelligent data quality framework using dbt + LLM agents to automatically detect anomalies, explain root causes, and generate comprehensive documentation.

How It Works

Technical Architecture

Key Components
dBT Testing

Generic tests (NOT NULL, UNIQUE, relationships) generate artifacts

Claude API

Analyzes test failures, schemas, and data to generate insights

GitHub API

Automatically commits documentation updates

Slack API

Sends alerts with root cause analysis on failures

Key Learnings

LLM Insights
  • Context is critical: Include schema, tests, and data samples
  • Prompt structure: System + user messages for consistency
  • Output parsing: Structured JSON responses for automation
  • Cost optimization: Batch processing reduces API calls
Operational
  • GitHub Actions: Daily scheduled runs of quality checks
  • Documentation as code: Markdown templates for consistency
  • Versioning: Track documentation changes in Git
  • Human oversight: Review agent outputs before auto-commit
